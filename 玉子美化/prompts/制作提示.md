# 玉子美化制作硬约束

## 流程与产物

- AI 负责主动引导并频繁建议下一步，但不替用户决定。默认按没有编程基础来说明：先讲看得见的结果和影响，术语第一次出现时顺手解释；每个用户可见阶段完成后和每个确认门槛前都给出具体建议与理由。
- 正式导入只接受真实、完整的 `mate.type === "chatSheets"` 模板；用户给出有效表格后立即 dry-run、建项和拆分，不先追问拆表方案。导入后默认把全部表加入队列。
- 拆分后再询问是直接开始美化、先讨论具体表/美化方向，还是先修改逐表 Markdown；Markdown 修改完成后由 AI 重建 generated 表格产物并刷新状态。
- 一次只处理当前表。用户可见流程固定为“讨论确认 → 一次制作完成 → 询问是否打开制作期模拟 → 当前表结果确认”；不得批量越过确认。
- 需求和设计每轮集中询问一组相关问题，每问都提供推荐答案与理由；无关问题分轮处理，能从真实文件查明的事实由 AI 自行读取。`notes/interview-<sheetKey>.md` 只按顺序保存访谈中的用户与 AI 原话，不写摘要、决定清单、推断状态、流程日志或实现记录。设计总结后必须询问用户是否还有补充，只有用户明确同意开工后才能编辑页面源码。
- 每页设计前读取 `docs/phone-ui-variables.md`，用其统一小手机尺寸、标题栏、图标和视觉变量。它只作参照，不得据此跨项目导入小手机 CSS、JavaScript 或资源；实现仍完全留在当前项目内。
- 酒馆接口资料按需读取：只有用户明确提出要使用酒馆、SillyTavern、TavernHelper 或酒馆输入框等能力时，才读取 `docs/architecture-notes.md` 和 `docs/sillytavern-api.txt`；没有明确需求时不读取。用户明确要求宿主 DOM 时，可以按设计中记录的选择器访问，并提供目标元素不存在时的降级处理。
- 页面默认使用单个 `mount.js`，把 HTML、CSS、SVG 和交互集中在一起；确有拆分必要或用户明确要求时才增加其他页面文件。
- 整页根容器必须撑满 `context.root` 的可用区域；Flex/Grid 的主布局方向按已确认设计显式声明，不能依赖 Flex 默认横向。内容区必须获得真实可用宽高，不能被挤成窄条或留下错误空白区。
- 用户同意开工后，页面实现、item 登记、路径核对和一次项目草稿检查连续完成，不逐项停顿或播报；只有失败、覆盖或新的决定点才说明。普通页面不运行全仓 `npm run verify`。
- `--dry-run` 只用于建项、导入、删除或迁移、覆盖和发布等风险动作；常规 item 登记和状态记录不重复预演。
- 每表访谈都要完整展示返回、上一张表、下一张表、编辑当前表四个 Runtime 导航动作，由用户逐项选择；AI 不得自行省略任何一项。
- 跳过必须由用户明确决定并记录非空原因。每表都要询问是否制作期模拟；用户可以跳过，状态必须如实记为 `not-run/passed/skipped/failed`。
- 用户选择制作期模拟后，页面出现后自动在内存 Mock 表新增一行完整测试内容，确认实时更新和主要交互，再执行清理/卸载、重新挂载及生命周期日志与控制台检查。整套检查连续完成，不逐项询问；没有异常和重复监听后才能记录 `passed`。测试行不得写入任何正式表格产物。
- 表结构修改前先说明影响并获得确认；只改 `tables/source/*.md`，重建 generated 后刷新状态。原始导入 JSON 永远不改。
- 删除 Markdown 表会让它从 generated 和制作队列直接消失；`project:skip-table` 只用于保留表格但不做美化。普通改表只跑当前项目快速检查，不跑全仓 verify。
- 最终分别交付 generated chatSheets、Bundle 和可编辑源码。Bundle 不建表、不写表、不迁移表。

## 表与 item

- 每个非跳过表在最终 Bundle 中唯一对应一个 item。`target.tableName` 按 Unicode NFKC 后精确匹配。
- item 只声明实际使用字段；声明字段必须存在于当前 generated 表头，真实表可以有额外字段或不同顺序。
- 表名、字段、队列、preview 记录或结构变化会使旧确认失效；重新汇总后才能发布。
- `project.json.tablesFile` 必须指向项目内 generated chatSheets，不能引用项目外表文件。

## Runtime API v1

- Bundle 固定为 `formatVersion: 2`、`apiVersion: 1`。
- 每个 item 的 `entry.mount` 指向 JavaScript 文本，并显式导出 `export function mount(context)` 或 async 形式。
- 只通过 `context.root` 操作页面；用 `context.getState()` / `context.subscribe()` 获取当前单表冻结快照。
- 绑定事件、订阅、定时器或观察器后返回幂等 disposer；正确响应 Abort，并处理晚到清理。
- 包内动态资源使用 `context.resolveAsset()`；四个导航 action 要处理 `navigated/stale/unavailable/failed`，异常后恢复按钮状态。
- Runtime 不提供跨表读取、数据库 CRUD、AI、世界书、手机内部事件或 `AutoCardUpdaterAPI`；`TavernHelper`、`SillyTavern.getContext()` 和宿主 DOM 只在用户明确要求并记录为当前 item 宿主依赖时使用。

## 源码与安全

- HTML、CSS、JavaScript、表文件和资源路径不得越出项目；拒绝绝对路径、`..`、URI、反斜杠或符号链接逃逸。
- CSS 必须用每页独立根 class 作用域化。表格数据默认写入 `textContent`；使用 HTML 或 URL 前明确校验与转义。
- 允许制作期项目内相对 JavaScript import 和 CSS `@import`，由打包器处理；最终 Bundle 不残留 module import 或 CSS `@import`。
- 禁止 `eval`、`new Function`、`iframe`、远程/绝对/裸模块、`import.meta.url`、JavaScript 相对 `fetch` 和未声明的外部应用全局对象；用户明确要求的宿主 DOM 选择器必须局部使用并有降级处理。
- 包内资源必须列入 `project.files` 并声明正确 MIME；二进制源码使用 `base64` encoding。
- 只改 source/project；Bundle 由 pack 重建并由 readback 对账，不直接手改生成物。

## 验证措辞

- 草稿检查证明当前源码合同；release check 证明发布门禁；readback 证明打包结果与源码对账。
- preview 只能称为“制作期模拟”，不能声称验证了真实 SillyTavern。
- 没有真实宿主证据时，Blob ESM、CSP、路由、数据库、IndexedDB、主题叠加、滚动恢复、资源 Blob URL 与页面生命周期均保持“待人工验收”。

## 宿主能力交接与生图讨论

普通制作不要求小手机源码。涉及字体、主题、生图等能力时，先读取 `docs/runtime/authoring-workflow.md`、`docs/runtime/host-capabilities.md` 和类型/示例，核对接口与模拟覆盖，再讨论效果。缺资料属于工具维护问题，不要求普通用户提供源码、不猜接口。

生图访谈必须先说明画框显示宽高、比例和窄屏变化，区分显示尺寸与出图分辨率；展示“表格字段＋构图要求”的完整拼接提示词，并集中询问用户要不要补充自己的提示词内容。只有确认后的构图与补充才能写入 `promptSuffix`。

制作期模拟永远只使用测试图片和内存数据，不调用真实生图、不读取密钥、不消耗额度，不提供切换真实生图的入口。用户明确要求最后统一模拟时，每表先记 `not-run`，不重复追问、不虚报通过；不省略逐表需求与结果确认。

## 弹窗制作分支（先选接口）

涉及弹窗时先读取 `docs/runtime/popup-authoring-workflow.md`。明确告诉用户“小手机有三个弹窗接口”：**弹幕**、**弹窗／浮窗**、**弹窗／插入正文**，先问做哪一个；不用“这份展示”代替“弹窗”。弹幕和弹窗／浮窗只能单表；只有弹窗／插入正文可以多表组合，选定它以后才问单表还是组合。已明确的选择不重复询问。内容、排版、交互在接口及来源确定之后再讨论。

弹窗访谈只确认接口、来源表、使用字段、内容排版、分页和用户可见交互。当前显示哪一行、是否最新、哪条记录触发以及宿主如何筛选数据，属于小手机运行时提供当前快照/事件的职责，不属于玉子美化决定。除非用户明确要求历史记录列表或行选择器，否则不得提出这些问题。

整页美化仍逐表；弹窗一次制作一个，正文组合弹窗的多个来源表共同组成一个制作单元，不拆散、不批量越过确认。使用 `project:add-display` 登记，不覆盖来源表的已有页面；模拟延后与真实状态记录规则不变。

图片能力必须单独确认：制作弹窗／插入正文时，必须主动问“要不要加生图按钮？”，并说明可以只共用页面图片而不加按钮；不得把某个用户选择不加变成通用默认。弹幕和弹窗／浮窗不支持点击生图，应说明限制，不提供不可用选项。图片标识也必须问：用户选择稳定标识字段，AI 检查真实值的空值、重复与稳定性；即使只有一行也不能省略，不擅自选 row_id、姓名、提示词或行位置。已明确的决定不重复问。标识确认是图片归属，不是弹窗显示记录筛选。

正文弹窗滚动由 AI 默认正确处理，不增加用户调查：弹窗／插入正文是酒馆正文的一部分，默认允许滚动传递给外层；确需内部滚动时，到达边缘或内容不足以滚动时仍应允许外层正文滚动。不得照搬手机整页的滚动隔离，默认不要设置 overscroll-behavior: contain/none 或拦截 wheel/touchmove；优先原生 CSS，不加滚轮转发补丁或兼容开关。只有用户明确要求锁定内部滚动时才讨论例外。本规则是制作提醒，不新增专门的模拟检查步骤或开工确认问题；已有模拟选择与如实记录规则不变。
