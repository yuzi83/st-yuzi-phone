# 宿主能力：制作前检查与生图讨论

本文件适用于普通用户制作美化，不要求小手机源码。维护工作台与小手机的开发任务不属于普通制作流程。

## 先检查，再讨论

AI 在用户提出字体、主题、生图或新展示需求时，先读取本文件和 `docs/runtime/host-capabilities.md`、配套类型声明及相关本地示例。先查清声明方式、调用方法、参数、结果、失败处理和模拟覆盖，再集中询问体验问题。不得先承诺交互，开工时才核对能力。

- 只用工作台随包资料和本地工具，不索要或查阅用户的小手机源码，不引用父项目依赖。
- “配置可以登记/打包”“本地测试通过”“真实宿主通过”是三种不同证据，不可互相替代。
- 缺资料时指出具体缺项，进入工作台维护，不猜方法名、不做假按钮、不让普通用户读源码排查。
- 不设置用户手机版本调查、升级询问或版本审批步骤。格式字段由工具根据声明处理，不交给用户选择技术编号。
- 有已有源码或访谈时先读它们，不让用户重复回答。

## 生图问题必须成组

先由 AI 查明并说明以下事实，不能反问用户现有页面的尺寸：

1. 图片框的显示宽高、长宽比、圆角/裁切方式，以及窄屏下如何变化。例如：112×112 CSS 像素，窄屏为100×100，始终1∶1，居中裁切。
2. 分清**显示尺寸、构图比例、出图分辨率**。小框不代表要生成同样小的低清图片；写“1∶1”提示词不是强制出图比例。当前公开调用没有宽高参数，不得伪造 width/height/aspectRatio。
3. 可用于人物描述的真实字段、标识同一个人物的稳定字段。标识必须非空且唯一，不能用行号；字段不存在时不能编造。

随后一轮集中询问相关问题，每项给出建议和理由：

- 主动确认是否使用生图按钮；未启用生图时不继续询问按钮细节。
- 用户选择图片的稳定标识字段（可单字段或组合）；展示真实值与检查结果。当前表为空时明确说明尚不能验证实际唯一性。改名会改变图片身份，空值或重复时暂停受影响内容的绑定。
- 已启用时确认按钮位置、大小、透明/底色、可点击热区；点击直接生成还是先编辑描述。
- 展示“选定字段＋构图要求”的**完整拼接提示词**，明确有哪些动态内容。构图要求包含用户同意的画框比例、主体位置、留白等。
- **主动问用户：要不要再补充自己的提示词内容？** 例如画风、背景、光线、服装。允许“不补充”；不得默认注入未经同意的画风，也不能因为要求直接生成就省略这项制作期讨论。
- 生成成功后的替换方式；等待、失败如何保留旧图；是否保留原上传/删除入口。

用户回答后汇总并问还有没有补充，明确同意开始后才制作。已确认项不重复询问。制作期讨论的附加描述写入画布 `promptSuffix`，不是要求终端使用者每次点按钮时重新输入。普通功能讨论不建立 `.scratch/`，逐表访谈只记录双方原话。

## 模拟永远只测试

制作期模拟没有真实生图开关：只使用本地测试图片、内存表和可控的成功/失败/关闭/不可用场景；不获取密钥、不调用生图服务、不消耗额度。沙箱禁止网络连接和外部图片请求。

- 模拟用例包括：提示词拼接、按钮防重、成功替换、失败保留、身份缺失/重复、页面失效、清理与重挂载。
- `subscribeImageGeneration` 模拟的是设置变化，不是生图进度广播。
- 当前模拟只对当前表提供生图数据；多表组合的其他表返回不可用，不能伪装为已覆盖。
- 用户明确选择最后统一模拟时，不每表重复询问；各表先记 `not-run`，统一模拟完成后逐表更新真实结果。不把延后写成 skipped 或 passed，也不取消逐表设计与结果确认。
- 真正使用与验收在小手机里进行，独立于制作期模拟。没有真实证据，不报告真实生图通过。

## 维护者交接责任

新增/修改宿主公开能力时，一起交付：工作台本地说明、类型、最小示例、配置校验、测试替身及对应测试。工作台必须在没有父目录的情况下继续运行。不得把内部服务对象、存储实现或密钥下放给美化页面。

## 弹窗制作分支（先选接口）

涉及弹窗时先读取 `docs/runtime/popup-authoring-workflow.md`。明确告诉用户“小手机有三个弹窗接口”：**弹幕**、**弹窗／浮窗**、**弹窗／插入正文**，先问做哪一个；不用“这份展示”代替“弹窗”。弹幕和弹窗／浮窗只能单表；只有弹窗／插入正文可以多表组合，选定它以后才问单表还是组合。已明确的选择不重复询问。内容、排版、交互在接口及来源确定之后再讨论。

弹窗访谈只确认接口、来源表、使用字段、内容排版、分页和用户可见交互。当前显示哪一行、是否最新、哪条记录触发以及宿主如何筛选数据，属于小手机运行时提供当前快照/事件的职责，不属于玉子美化决定。除非用户明确要求历史记录列表或行选择器，否则不得提出这些问题。

整页美化仍逐表；弹窗一次制作一个，正文组合弹窗的多个来源表共同组成一个制作单元，不拆散、不批量越过确认。使用 `project:add-display` 登记，不覆盖来源表的已有页面；模拟延后与真实状态记录规则不变。

图片能力必须单独确认：制作弹窗／插入正文时，必须主动问“要不要加生图按钮？”，并说明可以只共用页面图片而不加按钮；不得把某个用户选择不加变成通用默认。弹幕和弹窗／浮窗不支持点击生图，应说明限制，不提供不可用选项。图片标识也必须问：用户选择稳定标识字段，AI 检查真实值的空值、重复与稳定性；即使只有一行也不能省略，不擅自选 row_id、姓名、提示词或行位置。已明确的决定不重复问。标识确认是图片归属，不是弹窗显示记录筛选。
