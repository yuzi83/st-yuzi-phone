# 酒馆正文页面：全屏透明浮层美化方法总结

本文只总结 `酒馆助手脚本-弹幕.txt` 中最值得借鉴的部分：

> 如何在不修改酒馆正文结构的前提下，在正文页面上方叠加全屏弹幕、提示框、装饰动画、浮动窗口等视觉效果。

不讨论 AI 生成、气泡渐变、角色人设等业务功能。

---

## 一、核心结论

这套方法的本质不是“给正文消息添加元素”，而是：

1. 获取酒馆主页面的 `document`；
2. 在主页面 `body` 上创建一个独立的全屏容器；
3. 将容器固定在浏览器视口上；
4. 通过高 `z-index` 放到正文上方；
5. 让容器不拦截鼠标事件；
6. 将所有弹窗、装饰、动画元素添加到这个容器中；
7. 结束后删除临时元素。

可以把它理解为：

```text
酒馆正文页面
    ↓
额外盖一层透明玻璃
    ↓
在透明玻璃上放弹幕、提示、动画和装饰
```

正文本身不需要被改写，也不需要知道这些浮层的存在。

---

## 二、为什么必须操作酒馆主页面的 document

酒馆助手脚本通常运行在 JS-Slash-Runner 的 iframe 沙箱中。

因此，脚本自己的：

```js
document
```

不一定是酒馆聊天正文所在的页面。

参考脚本使用：

```js
const doc = window.parent.document;
```

这表示：

```text
当前 iframe 的脚本
        ↓
访问父级窗口
        ↓
拿到酒馆真正显示正文的 document
```

后续创建样式、创建浮层、添加弹窗，都应该使用这个主页面的 `document`：

```js
const hostDoc = window.parent.document;

const style = hostDoc.createElement('style');
const layer = hostDoc.createElement('div');
const popup = hostDoc.createElement('div');
```

如果误用 iframe 内部的 `document`，元素可能只出现在脚本沙箱页面中，而不是酒馆正文页面。

## 三、全屏透明层的关键 CSS

全屏浮层最关键的是以下几项：

```css
.overlay-layer {
  position: fixed;
  inset: 0;
  width: 100vw;
  height: 100vh;
  overflow: hidden;
  pointer-events: none;
  z-index: 9999;
}
```

### 1. `position: fixed`

浮层相对于浏览器视口定位，而不是相对于某一条聊天消息定位。

好处：

- 不需要修改酒馆消息 DOM；
- 不需要关心正文容器的层级结构；
- 页面滚动时，浮层仍然覆盖当前屏幕；
- 可以统一处理整个屏幕范围的装饰效果。

### 2. `inset: 0`

等价于：

```css
top: 0;
right: 0;
bottom: 0;
left: 0;
```

让浮层贴住视口四边。

也可以写成：

```css
top: 0;
left: 0;
width: 100vw;
height: 100vh;
```

### 3. `100vw` 和 `100vh`

浮层宽高始终按照用户当前浏览器视口计算。

因此它可以自动适应：

- 不同显示器；
- 不同浏览器窗口大小；
- 桌面端和移动端；
- 用户调整窗口尺寸；
- 酒馆页面布局变化。

不要把浮层尺寸写死成 `1920px`、`1080px` 等固定值。

### 4. `overflow: hidden`

限制浮层内部内容不要跑到视口之外。

特别适合：

- 从屏幕边缘进入的弹幕；
- 飘出屏幕的文字；
- 粒子效果；
- 全屏装饰动画。

### 5. `z-index`

例如：

```css
z-index: 9999;
```

让浮层通常显示在酒馆正文、聊天消息和普通控件之上。

如果还要在浮层上放一个可交互的控制面板，可以给控制面板更高的层级：

```css
.overlay-layer {
  z-index: 9999;
}

.overlay-panel {
  z-index: 10000;
  pointer-events: auto;
}
```

需要注意：`z-index` 不是绝对最高。如果酒馆自身的模态框或其他插件使用了更高的层级，它仍然可能盖住当前浮层。

## 四、为什么不会影响用户点击

全屏浮层最精妙的设置是：

```css
pointer-events: none;
```

它的含义是：

> 这个元素虽然覆盖在视觉上，但不参与鼠标命中测试。

因此，用户点击屏幕时，点击会穿过浮层，落到下面真正的酒馆正文或按钮上。

效果如下：

```text
视觉层：弹幕、动画、装饰
          ↓ 点击穿透
交互层：酒馆正文、输入框、按钮
```

这可以让浮层做到：

- 视觉上覆盖正文；
- 不遮挡正文；
- 不阻止用户滚动；
- 不阻止用户点击聊天消息；
- 不阻止用户输入；
- 不需要为每个浮层元素单独处理鼠标事件。

如果某一个元素确实需要交互，例如关闭按钮、设置面板、可拖动窗口，可以单独恢复事件：

```css
.overlay-panel {
  pointer-events: auto;
}
```

推荐原则：

```text
大容器 pointer-events: none
只有确实需要交互的子元素 pointer-events: auto
```

## 五、浮层元素应该如何定位

浮层内部的弹窗、文字和装饰一般使用：

```css
.overlay-item {
  position: absolute;
}
```

因为父层覆盖整个视口，所以子元素的坐标可以直接按屏幕坐标计算：

```js
const rect = layer.getBoundingClientRect();

item.style.left = `${Math.random() * rect.width}px`;
item.style.top = `${Math.random() * rect.height}px`;
```

常用定位方式：

### 1. 随机位置

适合：

- 弹幕；
- 气泡；
- 漂浮提示；
- 随机装饰。

### 2. 固定角落

适合：

- 右上角状态提示；
- 左下角通知；
- 屏幕边缘装饰；
- 全局快捷工具。

例如：

```css
right: 20px;
top: 80px;
```

### 3. 根据某个正文元素定位

如果以后需要让弹窗靠近某一条消息，可以额外获取正文元素的位置：

```js
const messageRect = messageElement.getBoundingClientRect();

item.style.left = `${messageRect.right + 10}px`;
item.style.top = `${messageRect.top}px`;
```

这属于“浮层定位到正文元素附近”，但仍然不需要把弹窗真正插入正文 DOM。

## 六、创建浮层的最小实现

下面是可复用的最小骨架：

```js
const hostDoc = window.parent.document;

// 防止重复创建
let layer = hostDoc.getElementById('my-overlay-layer');

if (!layer) {
  layer = hostDoc.createElement('div');
  layer.id = 'my-overlay-layer';

  Object.assign(layer.style, {
    position: 'fixed',
    inset: '0',
    width: '100vw',
    height: '100vh',
    overflow: 'hidden',
    pointerEvents: 'none',
    zIndex: '9999',
  });

  hostDoc.body.appendChild(layer);
}
```

然后添加一个临时元素：

```js
function addOverlayItem(text) {
  const item = hostDoc.createElement('div');

  item.textContent = text;

  Object.assign(item.style, {
    position: 'absolute',
    left: '100px',
    top: '100px',
    color: '#fff',
    pointerEvents: 'none',
  });

  layer.appendChild(item);

  return item;
}
```

使用：

```js
const item = addOverlayItem('这是一个覆盖在正文上方的提示');

setTimeout(() => {
  item.remove();
}, 4000);
```

这个骨架已经具备：

- 覆盖正文；
- 适应屏幕；
- 点击穿透；
- 独立管理；
- 临时显示；
- 自动清理。

## 七、推荐的浮层生命周期

一个稳定的浮层功能最好按照下面的生命周期设计：

```text
初始化
    ↓
清理旧样式和旧浮层
    ↓
注入 CSS
    ↓
创建全屏层
    ↓
添加临时子元素
    ↓
执行动画或等待超时
    ↓
删除子元素
    ↓
停止功能时删除全屏层
```

### 初始化时清理旧实例

可以通过固定 ID 查找并移除旧节点：

```js
const oldLayer = hostDoc.getElementById('my-overlay-layer');
if (oldLayer) oldLayer.remove();
```

这样可以避免脚本重复执行后出现：

- 多个透明层；
- 同一弹窗重复显示；
- 动画数量不断增加；
- 旧事件和旧定时器残留。

### 子元素及时删除

每一个临时弹窗、动画或弹幕都应该在结束后删除：

```js
setTimeout(() => item.remove(), duration);
```

否则长时间运行后会积累大量隐藏 DOM，影响性能。

### 停止功能时删除总层

停止插件时，可以直接删除整个层：

```js
layer.remove();
layer = null;
```

这样比逐个寻找和删除所有子元素更简单。

## 八、为什么这种方案适合酒馆美化

相比直接修改酒馆正文 DOM，全屏浮层有几个明显优势。

### 1. 与酒馆内部结构解耦

不依赖具体的消息 HTML 结构，不需要强依赖 `.mes`、消息 ID 属性或酒馆某个内部容器。

酒馆升级后，只要 `window.parent.document` 仍然可访问，浮层通常仍然可以工作。

### 2. 不污染正文数据

浮层只是页面上的临时视觉元素，不会：

- 修改聊天记录；
- 写入 AI 消息；
- 影响导出内容；
- 影响上下文；
- 影响世界书；
- 破坏消息重新渲染。

### 3. 适合各种视觉效果

同一套浮层基础设施可以承载：

- 弹幕；
- Toast 提示；
- 角色登场特效；
- 全屏闪光；
- 粒子；
- 雨雪效果；
- 漂浮表情；
- 屏幕边缘装饰；
- 阅读进度提示；
- 临时设置面板；
- 场景转场动画；
- 互动式按钮或窗口。

### 4. 自动适应画面

使用 `fixed`、`vw`、`vh` 和实时的 `getBoundingClientRect()`，可以根据用户当前窗口尺寸计算位置。

不要假设用户一定使用固定分辨率、固定缩放比例或固定窗口大小。

### 5. 默认不抢交互

全局层设置 `pointer-events: none`，只有需要交互的子元素开启 `pointer-events: auto`，可以最大限度避免影响酒馆正常使用。

## 九、借鉴时应该记住的设计原则

### 原则一：浮层是“覆盖层”，不是“正文子节点”

除非确实需要绑定某条消息，否则不要把美化元素直接插入消息 DOM。

优先考虑：

```text
独立浮层 + absolute 子元素
```

### 原则二：浮层和业务逻辑分离

建议分成两个模块：

```text
浮层管理器
    - 创建层
    - 添加元素
    - 删除元素
    - 清理层

业务逻辑
    - 什么时候显示
    - 显示什么文字
    - 显示哪个角色
```

以后更换弹幕、提示框、剧情特效时，不需要重写底层显示机制。

### 原则三：所有元素使用唯一命名空间

例如：

```text
my-overlay-layer
my-overlay-item
my-overlay-panel
```

避免和酒馆本体或其他插件的类名、ID、样式冲突。

### 原则四：所有临时元素必须可清理

至少要保存：

- 浮层 DOM 引用；
- 动画或定时器引用；
- 需要解绑的事件监听；
- 当前创建的子元素。

### 原则五：默认点击穿透

除非元素本身需要点击，否则都设置：

```css
pointer-events: none;
```

## 十一、性能与卡顿建议

全屏浮层本身通常不会明显消耗性能，真正可能导致卡顿的是浮层里面放置的元素数量和特效复杂度。

### 一般比较轻量的做法

- 少量文字、图片和提示框；
- 简单的淡入淡出；
- 使用 `opacity` 和 `transform` 做动画；
- 同时存在的装饰元素数量保持在合理范围内；
- 动画结束后及时删除元素。

### 容易增加性能压力的做法

- 同时创建大量移动元素；
- 大量使用 `filter: blur()`、`backdrop-filter`；
- 每个元素都添加复杂阴影；
- 全屏渐变、滤镜或粒子持续变化；
- 频繁创建、删除或重建大量 DOM；
- 每一帧都反复读取布局并修改位置；
- 同时播放很多 GIF、视频或高分辨率图片。

### 推荐规则

```text
1. 优先使用 opacity 和 transform 做动画
2. 尽量不要频繁修改 top、left、width、height
3. 给同时存在的浮层元素设置数量上限
4. 动画结束后及时删除元素
5. 少用大面积 blur、backdrop-filter 和复杂阴影
6. 不要每一帧重建整个浮层
7. 大量粒子不要创建大量 div，改用一个真正的 canvas
8. 浮层默认使用 pointer-events: none，交互控件再单独开启
```

大白话：

> 透明舞台本身不怎么耗性能，真正会卡的是舞台上的演员太多、灯光太复杂、特效太密集。

## 最终记忆版

以后想给酒馆正文页面做各种花里胡哨的视觉美化，只需要记住这套结构：

```text
1. window.parent.document
2. 创建一个全屏 div
3. position: fixed
4. inset: 0
5. width: 100vw
6. height: 100vh
7. overflow: hidden
8. pointer-events: none
9. z-index 设置得比正文高
10. 把弹窗和动画添加到这个 div 里
11. 到时间后删除
```

大白话就是：

> 在酒馆正文上面盖一层透明、全屏、不会挡点击的玻璃板。  
> 所有装饰都画在这块玻璃板上。  
> 玻璃板跟着用户屏幕自动适应，装饰显示完以后自己消失。
